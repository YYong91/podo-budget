# 사용 가이드 페이지 유지 규칙

## 기능 변경 시 가이드 업데이트
기능을 추가하거나 기존 기능을 변경했을 때, `frontend/src/pages/GuidePage.tsx`에 해당 내용이 반영되어야 하는지 확인한다.

- 새 기능 추가 → 해당 섹션에 설명 추가
- 기존 기능 변경 → 가이드 내 설명/예시 업데이트
- 기능 삭제 → 가이드에서 관련 내용 제거

## 기능 변경 시 새소식(changelog) 업데이트
사용자에게 보이는 기능을 추가/변경/수정했을 때, `frontend/src/data/changelogs.ts`를 업데이트한다.

### 업데이트가 필요한 경우
- 새 기능 추가 (페이지, 컴포넌트, API 연동 등)
- 기존 기능의 눈에 띄는 개선 (UI 변경, UX 개선 등)
- 사용자에게 영향을 주는 버그 수정

### 업데이트가 불필요한 경우
- 내부 리팩토링 (사용자에게 보이지 않는 변경)
- 코드 스타일/린트 수정
- 테스트 추가/수정
- 문서 업데이트

### 작성 방법
1. `changelogs` 배열 **맨 앞**에 새 항목 추가 (최신순 유지)
2. 기존 최신 버전과 같은 배포 주기면 해당 항목의 `items`에 추가
3. 새 배포 주기면 버전을 올려서 새 항목 생성
4. 태그: `신규` (새 기능), `개선` (기존 기능 향상), `수정` (버그 수정)

```typescript
// frontend/src/data/changelogs.ts 맨 앞에 추가
{
  version: '1.x.0',
  date: 'YYYY-MM-DD',
  title: '업데이트 제목',
  items: [
    { tag: '신규', text: '기능 설명' },
  ],
},
```
