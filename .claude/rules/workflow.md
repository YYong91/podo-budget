# 작업 워크플로우

## 자율 실행 원칙

- 작업 중간에 사용자에게 확인을 구하지 않고 끝까지 진행한다
- 판단이 필요한 경우 최선의 선택을 하고 결과만 보고한다
- 에러가 나면 스스로 원인을 파악하고 수정 후 계속 진행한다
- 작업 완료 후 한 번에 결과를 보고한다

## 대규모 작업 패턴

큰 기능 개발은 다음 순서로 진행한다:

1. **브레인스토밍** — 요구사항 정리, 접근법 2-3개 제안, 디자인 문서 작성
2. **구현 계획** — Phase별 태스크 분해, `docs/plans/` 에 저장
3. **워크트리 생성** — develop 기반 feature 브랜치 + 워크트리
4. **서브에이전트 실행** — Phase별로 서브에이전트 디스패치, 결과 리뷰
5. **테스트 확인** — BE pytest + FE lint/test/build 전체 통과
6. **PR 생성** — develop 대상

## 커밋 전 체크

커밋 전에 반드시 아래 사항을 확인한다:

1. **ruff 린트/포맷** — `ruff check --fix backend/` → `ruff format backend/`
2. **시크릿 스캔** — .env, API 키, SSH 키, 패스워드가 커밋에 포함되지 않는지 확인
3. **테스트 통과** — `pytest` 실행하여 기존 테스트 깨지지 않는지 확인
4. pre-commit 훅이 설치되어 있으면 자동으로 실행되지만, 수동 확인도 습관화

## 완료 보고

구현이 끝나면 도메인 관점에서 아래 3가지를 설명한다:
- **목표**: 사용자에게 어떤 가치를 제공하는지
- **원인**: 왜 이 작업이 필요했는지 (문제, 불편, 기회)
- **구현 방향**: 어떤 접근법을 선택했고 왜 그렇게 했는지

## 마무리 프로토콜
작업이 끝날 때마다 아래 파일들에 업데이트할 내용이 있는지 체크하고 반영한다:

1. **CLAUDE.md** — 프로젝트 구조, 명령어, 아키텍처 변경사항
2. **.claude/rules/*.md** — 새로 확립된 컨벤션이나 규칙
3. **docs/IMPLEMENTATION_STATUS.md** — 기능별 구현 현황
4. **frontend/src/data/changelogs.ts** — 사용자 대상 변경사항 (guide.md 규칙 참고)
