# 카테고리 마스터 정립 디자인

## 배경

현재 포도가계부의 카테고리는 시스템 카테고리(DB seed)가 없이 LLM 프롬프트에만 하드코딩되어 있다.
사용자가 지출을 입력할 때마다 가구/개인 스코프에 카테고리가 자동 생성되어 중복 데이터가 발생하고,
새 사용자는 카테고리 목록이 비어있는 상태로 시작한다.

운영 초반이므로 이 시점에 시스템 카테고리를 확립하고 기존 데이터를 정리한다.

## 목표

1. 시스템 카테고리 25개(지출 18 + 수입 7)를 DB에 seed
2. 기존 가구/개인 카테고리의 FK를 시스템 카테고리로 re-link 후 중복 삭제
3. prompts.py의 하드코딩 카테고리를 새 마스터로 교체
4. 프론트엔드에서 시스템 카테고리 수정/삭제 불가 UI 처리

## 마이그레이션 전략

### Alembic migration

```
1. 시스템 카테고리 25개 INSERT (user_id=NULL, household_id=NULL)

2. 이름 변경 처리 (각 가구별):
   기존 "카페/간식" → expenses/incomes/budgets FK를 시스템 "카페/음료"로 re-link → 가구 카테고리 삭제
   기존 "의료"     → 시스템 "의료/건강"으로 re-link → 삭제
   기존 "교육"     → 시스템 "교육/자기계발"로 re-link → 삭제
   기존 "구독서비스" → 시스템 "구독"으로 re-link → 삭제
   기존 "이자/배당" → 시스템 "투자/배당"으로 re-link → 삭제

3. 이름 동일한 기존 가구/개인 카테고리 (예: "식비"):
   expenses/incomes/budgets FK를 시스템 카테고리로 re-link → 가구 카테고리 삭제

4. 사용자 커스텀 카테고리 (시스템 목록에 없는 이름):
   그대로 유지

5. CategoryMapping seed (user_id=NULL, household_id=NULL):
   "카페/간식" → "카페/음료"
   "의료" → "의료/건강"
   "교육" → "교육/자기계발"
   "구독서비스" → "구독"
   "이자/배당" → "투자/배당"
```

### 위험도

- 기존 데이터: FK re-link으로 안전하게 이전, 커스텀 카테고리 유지
- 롤백: downgrade에서 시스템 카테고리 삭제 (FK가 걸린 거래는 category_id=NULL로)

## 백엔드 변경

### schemas/category.py
- `CategoryResponse`에 `is_system: bool` 필드 추가
- `user_id is None and household_id is None`이면 `is_system=True`

### prompts.py
- EXPENSE_PARSER_SYSTEM_PROMPT: 카테고리 목록을 새 마스터 18개로 교체
- OCR_EXPENSE_PARSER_PROMPT: 동일하게 교체

### api/categories.py
- reorder: 시스템 카테고리 sort_order 변경 불가 (이미 구현됨)
- GET 목록: 변경 없음 (시스템 + 가구 + 솔로 모두 반환)

## 프론트엔드 변경

### types/index.ts
- `Category` 인터페이스에 `is_system: boolean` 추가

### CategoryManager.tsx
- `is_system=true`: 수정/삭제 버튼 숨김, 순서변경 버튼 비활성화
- 시스템 카테고리 시각적 구분 (잠금 아이콘 또는 뱃지)

### CategoryBottomSheet.tsx
- 변경 없음 (시스템 카테고리도 선택 가능)
