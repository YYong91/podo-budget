# 지출/수입 예정 섹션 설계

> GitHub Issue: #506 — 달력에 정기거래 예정일 및 예상금액 표시

## 배경

사용자가 이번 달 정기거래(OTT, 구독 서비스 등)가 언제 얼마나 나가는지 가계부 홈에서 바로 파악하고 싶다. 현재는 정기거래 관리 화면까지 가야만 확인 가능하고, 도래한 정기거래는 상단 PendingRecurring 카드로만 표시된다.

## 설계 결정 과정

- 달력 셀에 도트/금액 표시 → 기각: 도트가 정기거래를 뜻하는지 사용자가 인지하기 어려움
- 달력 탭 시 요약 카드 → 기각: 탭 액션이 "날짜 이동 + 카드 표시" 두 가지가 됨
- 거래 목록에 예정 항목 혼합 → 기각: 월초에 여러 날짜의 예정 항목이 목록을 어지럽힘
- **달력과 거래 목록 사이에 독립 섹션** → 채택: 명확하고 기존 동작 변경 없음

## 기능 명세

### 1. 섹션 위치

달력(MiniCalendar)과 거래 목록 사이. 기존 PendingRecurring 카드를 대체한다.

### 2. 섹션 타이틀 (동적)

| 상태 | 타이틀 |
|------|--------|
| 지출 정기거래만 있음 | 지출 예정 |
| 수입 정기거래만 있음 | 수입 예정 |
| 둘 다 있음 | 지출/수입 예정 |
| 정기거래 없음 | 섹션 미표시 |

### 3. 접힌 상태 (기본)

```
┌─ 지출 예정 ─────── 3건 ──────┐
│ 40,700원               [▼]  │
└──────────────────────────────┘
```

- 건수 + 총액 표시
- 지출/수입 둘 다 있을 때: `지출 40,700원 · 수입 2,000,000원`

### 4. 펼친 상태

```
┌─ 지출 예정 ─────── 2건 ──────┐
│ 25일 유튜브 프리미엄 14,900원  │
│ 28일 스포티파이     10,900원  │
│                               │
│ 남은 지출 25,800원             │
│                      [접기 ▲] │
└──────────────────────────────┘
```

- 날짜순 정렬
- 처리된 건(실행/건너뛰기 완료)은 표시하지 않음
- 미처리 건만 표시
- 다 처리하면 섹션 자체가 사라짐

### 5. 도래한 미처리 항목 (액션 버튼)

`next_due_date <= today`인 미처리 항목에 등록/건너뛰기 버튼 노출:

```
│ ● 1일  넷플릭스      14,900원  │
│    [등록]  [건너뛰기]          │
│ 25일 유튜브 프리미엄 14,900원  │
│ 28일 스포티파이     10,900원  │
```

- 등록: 기존 `recurringApi.execute()` 호출
- 건너뛰기: 기존 `recurringApi.skip()` 호출
- 처리 후 해당 항목 목록에서 제거, 건수/총액 갱신

### 6. 자동 펼침/접힘 로직

| 조건 | 섹션 상태 |
|------|----------|
| 도래 미처리 있음 + 오늘 첫 진입 | 자동 펼침 |
| 도래 미처리 있음 + 사용자가 접음 | 그 날은 접힘 유지 |
| 도래 미처리 있음 + 다음 날 진입 | 다시 자동 펼침 |
| 도래 미처리 없음 | 접힘 |

- localStorage에 `{ date: 'YYYY-MM-DD', collapsed: true }` 저장
- 날짜가 바뀌면 리셋

### 7. 기존 PendingRecurring 카드 통합

- `PendingRecurring` 컴포넌트 제거
- 도래 항목의 등록/건너뛰기 기능을 이 섹션이 흡수

## 데이터 요구사항

### 표시 범위

- **현재 달만 표시**. 다른 달로 네비게이션하면 섹션 미표시.
- **멤버 필터 무시**. 공유 가계부이므로 가구의 모든 정기거래를 표시.
- **비활성(`is_active: false`) 정기거래 제외**.

### 미처리 판별 로직

활성 정기거래 중 `next_due_date`가 이번 달 범위(1일~말일) 안에 있는 것 = 미처리 예정. 처리(실행/건너뛰기)하면 `next_due_date`가 다음 달로 이동하므로 자동으로 목록에서 빠진다.

### 데이터 전략

`GET /recurring` (전체) 한 번만 호출하고 FE에서 필터링:
- `is_active === true`만
- `next_due_date`가 이번 달 범위(1일~말일) → 미처리 예정 목록
- 그 중 `next_due_date <= today` → 도래 항목 (액션 버튼 노출)

`GET /recurring/pending`은 별도 호출하지 않음 (전체에서 필터 가능).

| API | 용도 |
|-----|------|
| `GET /recurring` | 활성 정기거래 전체 조회 → FE에서 이번 달 필터링 |
| `POST /recurring/{id}/execute` | 등록 |
| `POST /recurring/{id}/skip` | 건너뛰기 |

새 API 불필요. 정기거래는 가구당 5-10건 수준이므로 전체 조회 후 FE 필터링으로 충분.

### "남은 지출/수입" 계산

표시된 미처리 항목의 합계 = 남은 금액. 처리된 건은 목록에 안 보이므로 별도 계산 불필요.

### 월말 경계 처리

`day_of_month: 31`인 정기거래가 30일까지인 달에도 정상 표시. 백엔드 `calculate_next_due_date`에서 월말 조정하여 `next_due_date`를 설정하므로, FE는 `next_due_date` 값만 참조하면 됨.

## 테스트 계획

### 프론트엔드
- 정기거래 없을 때 섹션 미표시
- 지출만 → "지출 예정" 타이틀
- 수입만 → "수입 예정" 타이틀
- 둘 다 → "지출/수입 예정" 타이틀
- 접힘 상태: 건수 + 총액 표시
- 펼침 시 날짜순 목록 (미처리만)
- 도래 미처리 항목에 등록/건너뛰기 버튼
- 등록/건너뛰기 후 항목 제거 및 갱신
- 모든 항목 처리 후 섹션 사라짐
- 자동 펼침: 도래 미처리 있을 때 첫 진입 시 펼침
- 수동 접힘: localStorage로 그 날 유지
- 다음 날 미처리 남아있으면 다시 펼침
