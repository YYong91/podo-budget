# 자산 기능 비활성화 + 플로팅 탭바 + 즉시 입력 UX

## 목적

1. 자산 기능을 피처 플래그로 비활성화하여 가계부 핵심에 집중 + 성능 개선
2. 하단 네비게이션을 iOS 26 리퀴드 글래스 스타일 플로팅 아일랜드로 변경
3. 거래 입력 플로우를 메신저 스타일로 단순화 (4-5스텝 → 1스텝)

## 스코프

- **대상**: 프론트엔드 전체 (Layout, 라우팅, InsightsPage, GuidePage 등) + GitHub Actions + 백엔드 일부
- **제외**: 백엔드 API/모델 삭제 (피처 플래그로 숨기기만, DB 데이터 보존)
- **접근법**: 환경변수 `VITE_FEATURE_ASSETS=false`로 on/off 제어

## 서브프로젝트 2: 플로팅 아일랜드 탭바

### 디자인 컨셉

iOS 26 리퀴드 글래스 스타일 — 하단 중앙에 둥근 아일랜드가 떠있는 형태.
Apple 시계/단축어 앱의 3탭 가운데 배치 참조.

### 레이아웃

```
[콘텐츠 영역]

                                              ┌────┐
  ┌──────────────────────────────────┐        │ ✏️ │
  │  [가계부]   [돌아보기]   [더보기]  │        │    │
  └──────────────────────────────────┘        └────┘
            네비게이션 아일랜드              입력 버튼
```

- 네비게이션: 3탭 아일랜드, 하단 중앙-좌측 배치
- 입력 버튼: 원형, 아일랜드 오른쪽에 별도 배치
- 둘 다 `position: fixed; bottom` + 안전 영역(safe-area) 대응

### 아일랜드 스타일

```css
/* 네비게이션 아일랜드 */
- 배경: backdrop-blur + 반투명 (glass morphism)
- 라이트: bg-white/70 backdrop-blur-xl
- 다크: bg-[#1a1525]/70 backdrop-blur-xl (grape 톤 다크)
- 모서리: rounded-full (완전 둥글림)
- 그림자: shadow-lg + border border-white/20
- 패딩: px-6 py-2
- 아이콘 + 라벨 (활성 탭: grape-600, 비활성: text-muted)

/* 입력 버튼 */
- 배경: grape-600 (solid — 가장 중요한 액션이므로 불투명 강조)
- 크기: 48x48px 원형
- 아이콘: 연필(Pencil) 또는 플러스(Plus) — white
- 그림자: shadow-lg
```

### 데스크톱 (md 이상)

- 기존 사이드바 유지 (변경 없음)
- 하단 플로팅 탭바는 모바일(md 미만)에서만 표시
- 입력 버튼은 데스크톱에서도 우하단 플로팅으로 표시

### 콘텐츠 영역 패딩

- 기존: `pb-40` (전체 너비 탭바 높이만큼)
- 변경: `pb-24` 정도로 축소 (아일랜드가 더 작으므로)
- 아일랜드가 콘텐츠 위에 떠있으므로 겹침 고려

## 서브프로젝트 3: 즉시 입력 UX

### 입력 플로우

```
1. 입력 버튼(✏️) 탭
2. 탭바 아일랜드가 입력창으로 모핑 (애니메이션)
3. 키보드 올라옴 + 텍스트 입력
4. 전송 버튼 탭 (또는 Enter)
5. LLM 파싱 → 즉시 저장 (프리뷰 폼 없음)
6. 입력창 → 탭바로 복귀 + 성공 토스트 표시
```

### 입력창 UI

```
[입력 모드 — 탭바가 변환]
┌────────────────────────────────────────┐
│  점심 김치찌개 8000원              [→] │
└────────────────────────────────────────┘
           키보드
```

- 탭바 아일랜드와 동일한 위치/너비에서 입력창으로 전환
- 입력 버튼도 전송 버튼(→)으로 변환
- 배경: 동일한 glass morphism 스타일
- placeholder: "지출/수입을 입력하세요" 또는 "오늘 점심 8000원"
- 입력창 밖 탭 또는 ESC → 입력 취소, 탭바 복귀

### 모핑 애니메이션

```
[탭바 상태]
  ┌─ 아이콘 ─ 아이콘 ─ 아이콘 ┐  ┌✏️┐

  ↓ 0.25s ease-out 전환

[입력 상태]
  ┌─ placeholder...      [→] ─┐
```

- 탭바 아이콘들이 fade out → 입력창이 fade in
- 아일랜드 너비가 입력 버튼까지 확장 (하나의 바로 합쳐짐)
- `transition` 기반 — `width`, `opacity`, `border-radius` 전환

### LLM 파싱 → 즉시 저장

기존 `POST /api/chat` 엔드포인트를 활용하되, **프리뷰 모드를 건너뜀**:
1. 텍스트를 LLM에 전송 → 파싱 결과 수신
2. 파싱 성공 → 바로 `POST /api/expenses` 또는 `POST /api/income`으로 저장
3. 프리뷰 확인 스텝 없음

이미 백엔드에 `/api/chat` → 파싱 → 저장 파이프라인이 있으므로 프론트에서 프리뷰 UI만 스킵하면 됨.

### 성공 토스트 (하단 카드형)

```
[성공 — 탭바 바로 위]
┌──────────────────────────────────┐
│  🍚 김치찌개                      │
│  식비 · ₩8,000         수정 →    │
└──────────────────────────────────┘
```

**스타일:**
- 배경: `surface-card` + `border-l-4 border-grape-400` (왼쪽 포인트 라인)
- 카테고리 이모지 좌측
- 우측 "수정 →" grape-600 텍스트 — 탭하면 해당 거래 상세 페이지로 이동
- 3초 후 자동 사라짐 (slide-down 애니메이션)
- 위치: 탭바 아일랜드 바로 위 (`bottom: 탭바높이 + 12px`)

### 실패 토스트

**파싱 실패:**
```
┌──────────────────────────────────────┐
│  ⚠️ 거래 정보를 인식하지 못했어요      │
│  금액을 포함해서 다시 입력해주세요      │
└──────────────────────────────────────┘
```
- 입력창 유지 (닫히지 않음) — 바로 재입력 가능
- warm-500 왼쪽 포인트 라인

**서버 에러:**
```
┌──────────────────────────────────────┐
│  ❌ 저장에 실패했어요                  │
│  점심 김치찌개 8000원    다시 시도 →   │
└──────────────────────────────────────┘
```
- 입력 텍스트 보존 — "다시 시도 →" 탭하면 재전송
- rose-500 왼쪽 포인트 라인

## 기존 입력 플로우와의 관계

### 삭제되는 것
- FAB (플로팅 액션 버튼) 컴포넌트 — `FloatingActionButton`
- 유형 선택 모달 (지출/수입 선택)
- 프리뷰 확인 폼 (TransactionForm의 프리뷰 모드)

### 유지되는 것
- `TransactionForm` 컴포넌트 자체 — 직접 입력 모드(폼 필드)는 유지
  - 설정에서 "직접 입력 모드"를 선택한 사용자를 위해
  - 또는 입력 후 상세 페이지에서 수정할 때
- `ExpenseDetail` / `IncomeDetail` — 수정 시 사용
- `/expense/new`, `/income/new` 라우트 — 직접 URL 접근 시 폼 모드

### 지출/수입 자동 판별

현재는 유형 선택 모달에서 사용자가 직접 "지출"/"수입"을 고르는데, 즉시 입력에서는 **LLM이 자동 판별**:
- "월급 300만원" → 수입
- "점심 8000원" → 지출
- 애매한 경우 → 지출로 기본 처리 (가계부 앱에서 지출이 압도적 다수)

이미 백엔드 `/api/chat`에 컨텍스트 탐지 로직이 있으므로 활용.
