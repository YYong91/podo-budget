# 가계부 통합 목록 페이지 리뉴얼

## 개요

기존 3개 목록 페이지(ExpenseList, IncomeList, TransactionList)를 하나의 통합 페이지로 대체한다. 토스 가계부 스타일의 월별 뷰 + 미니 캘린더 + 날짜별 그룹핑 구조로, 모바일 중심 UX를 제공한다.

## 현재 문제점

1. **잘못된 정렬**: TransactionList에서 같은 날짜인데 지출이 먼저 나오고 그 뒤에 수입이 나옴 (interleave 방식의 결함)
2. **모바일 금액 짤림**: 테이블 레이아웃에서 내용이 길면 금액이 보이지 않아 가로 스크롤 필요
3. **모바일 카테고리 숨김**: 반응형으로 카테고리 컬럼이 숨겨져 확인/수정 불가
4. **페이지네이션 불편**: 모바일에서 20건씩 넘겨보는 UX가 번거로움

## 페이지 구조

위에서 아래 순서로 배치:

```
┌─────────────────────────────┐
│       ◀  2026년 3월  ▶      │  월 네비게이션
├─────────────────────────────┤
│ 지출 ₩1,230,000  수입 ₩3,500,000 │  요약 + 필터
├─────────────────────────────┤
│  일  월  화  수  목  금  토  │
│         미니 캘린더           │  상시 펼침, 스크롤 시 자연스럽게 올라감
│   각 날짜 셀에 -8k, +50k    │
├─────────────────────────────┤
│  3월 13일 목요일    [sticky] │  날짜 구분 헤더
│ ┌───────────────────────┐   │
│ │ 점심 김치찌개    -₩8,000│   │  거래 항목 (2줄)
│ │ 🍽 식비               │   │
│ ├───────────────────────┤   │
│ │ 월급          +₩3,500,000│  │
│ │ 💰 급여               │   │
│ └───────────────────────┘   │
│  3월 12일 수요일             │
│  ...                        │
└─────────────────────────────┘
```

## 상세 설계

### 1. 월 네비게이션

- 상단에 `◀ 2026년 3월 ▶` 표시
- 좌우 화살표로 이전/다음 달 이동
- 월 변경 시 해당 월의 지출+수입 전체를 백엔드에서 한 번에 로드
- 초기 진입 시 현재 월 표시

### 2. 요약 + 필터 (금액 탭 = 필터)

- 한 줄에 `지출 ₩1,230,000` | `수입 ₩3,500,000` 표시
- 해당 월 전체 데이터에서 합계 계산 (프론트 클라이언트 사이드)
- **필터 동작**:
  - 기본: 둘 다 활성 (전체 보기)
  - 지출 금액 탭 → 지출만 필터 (수입 흐리게 `opacity-40`), 다시 탭 → 전체 복귀
  - 수입 금액 탭 → 수입만 필터 (지출 흐리게), 다시 탭 → 전체 복귀
  - 선택된 항목: 볼드 + grape(지출)/leaf(수입) 컬러
  - 미선택: `opacity-40`
- 필터 변경 시 캘린더의 날짜별 금액과 리스트가 함께 반영됨

### 3. 미니 캘린더

- 해당 월 전체 달력 그리드 (7열 x 4~6행)
- **날짜 셀 내용**:
  - 날짜 숫자
  - 지출 합계: `-8k` (grape 컬러, 소형 텍스트)
  - 수입 합계: `+50k` (leaf 컬러, 소형 텍스트)
    - 금액 축약 규칙: 1만 미만은 그대로(`-8,000`), 1만 이상은 만 단위(`-1.2만`), 100만 이상은 백만 단위(`-150만`)
  - 거래 없는 날은 금액 미표시
- **오늘 날짜**: grape 원형 배경으로 하이라이트
- **날짜 탭**: 아래 리스트에서 해당 날짜 구분 헤더로 자동 스크롤 (`scrollIntoView`). 스티키 헤더 높이만큼 `scroll-margin-top`을 CSS로 설정하여 헤더 뒤에 가리지 않도록 처리
- **스크롤 동작**: 일반 흐름으로 배치, 스크롤 내리면 자연스럽게 올라가서 안 보임 (sticky 아님)
- 필터(지출만/수입만) 적용 시 캘린더 금액도 필터된 값으로 표시

### 4. 거래 리스트

#### 날짜 구분 헤더
- "3월 13일 목요일" 형식
- **sticky 동작**: 스크롤 시 상단에 고정, 다음 날짜 헤더가 올라오면 교체됨
- 캘린더가 올라간 뒤 sticky 위치에 고정

#### 거래 항목 (2줄 구조)
- **1줄**: 설명(좌측) + 금액(우측, 우정렬)
  - 지출: `-₩8,000` (기본 텍스트 컬러)
  - 수입: `+₩3,500,000` (leaf 컬러)
- **2줄**: 카테고리 뱃지
  - 뱃지 스타일: 작은 pill 형태
  - 탭 시 바텀시트로 카테고리 변경 가능
- **추가 뱃지**: 정기 거래(`정기`), 통계 제외(`통계제외`) — 기존과 동일하게 유지
- **항목 탭**: 상세 페이지(ExpenseDetail/IncomeDetail)로 이동 (기존 동작 유지)
- 카테고리 뱃지 탭은 이벤트 전파 중단 (상세 이동 방지)

#### 정렬
- 날짜 역순 (최신 날짜가 위)
- 같은 날짜 내에서는 `id` 역순 (최근 등록이 위)
- 지출/수입 구분 없이 시간순으로 섞임

#### 로딩 상태
- 월 전환 시 캘린더 + 리스트 영역에 스켈레톤 UI 표시
- 캘린더: 그리드 형태 스켈레톤
- 리스트: 2~3개의 거래 항목 스켈레톤

#### 빈 상태
- 해당 월에 거래가 없으면 EmptyState 컴포넌트 표시
- 필터 적용으로 결과 없을 때도 적절한 메시지 표시

### 5. 카테고리 바텀시트

- 카테고리 뱃지 탭 시 하단에서 올라오는 시트
- **구현**: CSS transition + 커스텀 구현 (별도 라이브러리 없이). 백드롭 오버레이 + 시트 슬라이드업 애니메이션
- **내용**: 해당 거래 타입(지출/수입)의 카테고리 목록만 표시
- **선택**: 카테고리 탭 시 즉시 API 호출로 업데이트, 시트 닫힘
- **닫기**: 백드롭 탭 또는 ESC 키로 닫기
- **PC 대응**: 동일 컴포넌트가 중앙 모달로 표시 (`md:` 브레이크포인트 기준 반응형)
- 로딩 중 스피너 표시, 실패 시 토스트 에러 메시지

### 6. 반응형 대응

- **모바일 (기본)**: 위 구조 그대로, 2줄 거래 항목
- **PC**: 동일 레이아웃, max-width 제한으로 중앙 정렬. 바텀시트 → 중앙 모달

## 데이터 흐름

### 백엔드 API

기존 API의 `start_date`, `end_date` 파라미터를 활용하여 월 단위 조회:

```
GET /api/expenses?start_date=2026-03-01&end_date=2026-03-31&limit=1000&household_id=1
GET /api/income?start_date=2026-03-01&end_date=2026-03-31&limit=1000&household_id=1
```

- **백엔드 변경 필요**: 현재 `limit`의 최대값이 100으로 제한되어 있음. 월 단위 전체 조회를 위해 `le=100` → `le=1000`으로 상향 (개인 가계부 특성상 월 1000건 이상은 비현실적)
- `end_date`는 해당 월의 마지막 날짜를 정확히 계산하여 전달 (예: 2월은 28/29일)
- 두 API를 `Promise.all`로 병렬 호출
- `household_id`는 `useHouseholdStore`의 `activeHouseholdId`에서 가져옴

### 프론트엔드 데이터 처리

1. **병합**: 지출+수입 배열을 합쳐서 `date` 기준 역순 정렬 (같은 날짜 내에서는 `id` 역순 — `created_at`은 프론트 타입에 있으나 `id`가 더 안정적)
2. **날짜별 그룹핑**: 날짜 문자열 기준으로 `Map<string, Transaction[]>` 생성
3. **캘린더 데이터**: 날짜별 지출 합계, 수입 합계 계산
4. **요약 데이터**: 월 전체 지출 합계, 수입 합계 계산
5. **필터링**: 전체/지출만/수입만 상태에 따라 클라이언트에서 필터 (원본 데이터 유지)

### 상태 관리

- `currentMonth`: `Date` — 현재 보고 있는 월 (URL 파라미터 `month=2026-03`로 동기화)
- `filter`: `'all' | 'expense' | 'income'` — 필터 상태
- `transactions`: 백엔드에서 받은 원본 데이터
- URL 파라미터로 월과 필터 상태를 유지하여 뒤로가기/공유 가능

### 기존 필터 기능 처리

- **카테고리 필터**: 이번 리뉴얼에서는 제거. 카테고리별 분석은 인사이트/리포트 페이지 역할
- **멤버 필터**: 이번 리뉴얼에서는 제거. 가구 멤버별 조회는 추후 필요 시 추가
- **날짜 범위 프리셋**: 월 네비게이션으로 대체
- **정렬 토글**: 날짜 역순 고정으로 단순화
